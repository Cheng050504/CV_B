# Resume Builder — CV & Cover Letter Generator

A web app that turns a multi-step form into a polished, recruiter-ready CV and cover letter. Built with Flask + DOCX templating, extended with AI-assisted bullet rewriting, stateless serverless-friendly document generation, and a pluggable template registry (Finance / Tech / Generic).

> Goal: **fill out a form in 3 minutes, download a formatted DOCX and PDF in one click** — no Word expertise needed.

---

## Why I Built This

Writing a good CV is mostly three painful things:
1. Fighting Word formatting every time you add a bullet.
2. Starting a cover letter from a blank page.
3. Keeping several versions in sync for different roles.

This project solves (1) by separating **content** (the form) from **presentation** (a reusable DOCX template with placeholders). It solves (2) with an optional LLM draft button. And it leaves the door open to (3) via a template registry that can host multiple styles (Finance, Tech, Generic, …) behind one form.

It's also a deliberately minimal full-stack sample that shows:
- How to do **precise, run-level DOCX placeholder replacement** without breaking bold/italic formatting.
- How to build a **serverless-friendly document pipeline** that never relies on a writable filesystem surviving between requests.
- How to keep the frontend **framework-free** yet still ship a clean multi-step form, draft persistence, live validation, and a loading state.

---

## Features

- **5-step form** (Personal → Education → Experience → Skills → Cover Letter) with per-step validation and a progress bar.
- **Template registry** — pick a style card (Finance is live; Tech & Generic are scaffolded).
- **Draft autosave** — every keystroke is mirrored to `localStorage`; reload-safe. One-click "Clear draft" and "Load sample data".
- **Unlimited education / experience blocks** that clone the first template block *with its original formatting preserved*.
- **Cross-run DOCX replacement** that handles placeholders split across multiple `<w:r>` runs (e.g. Word quietly splitting `[Company Name]` into four runs after a spell-check).
- **Optional AI rewrite** — "Improve with AI" button on each experience bullet and a "Draft cover letter body" button on step 5. Uses any OpenAI-compatible endpoint (OpenAI, Ollama, OpenRouter, …) via env vars.
- **PDF preview in-browser** when a PDF converter is available (docx2pdf on desktop, LibreOffice headless on Linux), with graceful DOCX-only fallback.
- **Stateless downloads** — generated bytes are streamed as base64 data URIs, so nothing relies on `/tmp` persisting between serverless invocations.

## Architecture

```
        ┌────────────────────────────────────────────────────────┐
        │                     Browser (form.html)                │
        │  • multi-step form      • localStorage autosave        │
        │  • per-step validation  • AI rewrite buttons           │
        └───────────────┬────────────────────────────────────────┘
                        │ POST /generate  (form-encoded)
                        │ POST /api/llm/* (JSON)
                        ▼
        ┌────────────────────────────────────────────────────────┐
        │                      Flask app                         │
        │                                                        │
        │   routes.py          services/docx_renderer.py         │
        │   ─ /  /build        ─ replace_in_runs_preserve()      │
        │   ─ /generate        ─ materialize_experiences()       │
        │   ─ /preview         ─ build_documents()               │
        │   ─ /api/llm/*                                         │
        │                      services/pdf_converter.py         │
        │   templates_registry ─ docx2pdf  → LibreOffice         │
        │                                                        │
        │                      services/llm.py                   │
        │                      ─ OpenAI-compatible client        │
        └───────────────┬────────────────────────────────────────┘
                        │
                        ▼
        ┌────────────────────────────────────────────────────────┐
        │       docx_templates/*.docx  (Finance live, Tech/       │
        │       Generic scaffolded)                               │
        │                                                         │
        │       Bytes returned in-memory — no disk writes on the  │
        │       hot path, no cross-invocation file dependencies.  │
        └────────────────────────────────────────────────────────┘
```

### Key design choices

| Choice | Why |
|---|---|
| Run-preserving replacement | Word often splits a placeholder like `[Company Name]` across several runs. A naïve `paragraph.text = ...` wipes bold/italic. I rebuild the full string, find longest-first non-overlapping matches, and edit runs in place from right to left. |
| In-memory DOCX → base64 `data:` URIs | Serverless (Vercel, Lambda) cannot guarantee `/tmp` persists across invocations, so a "save then re-download" flow 404s in production. Streaming the file bytes into the response HTML removes the whole class of bugs. |
| App factory + service modules | Keeps routes thin, makes the renderer unit-testable without a live Flask request. |
| OpenAI-compatible LLM client | Works with OpenAI, OpenRouter, Ollama, LM Studio, vLLM, Anthropic-compat proxies — the same `base_url + api_key + model` triple. Falls back to a helpful 503 if the user hasn't configured a key. |

## Tech Stack

- **Backend**: Python 3.10+, Flask 3, python-docx, lxml
- **Frontend**: Jinja2 templates, vanilla JS (no build step), hand-rolled CSS design tokens
- **DOCX → PDF**: `docx2pdf` (needs Word) → LibreOffice headless (`soffice`) — both optional
- **LLM** *(optional)*: any OpenAI-compatible chat completions endpoint
- **Deployment**: works locally via `python app.py`; ships with a `vercel.json` for serverless

## Setup

### Prerequisites
- Python 3.10+
- *(Optional, for PDF)* Microsoft Word (`docx2pdf`) **or** LibreOffice (`soffice` on PATH)
- *(Optional, for AI)* An OpenAI-compatible API key

### Install

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate

pip install -r requirements.txt
```

### Configure (optional)

Copy `.env.example` to `.env` and fill in whatever you want to use:

```bash
SECRET_KEY=change-me-in-prod
LLM_API_KEY=sk-...                       # leave blank to disable AI features
LLM_BASE_URL=https://api.openai.com/v1   # or http://localhost:11434/v1 for Ollama
LLM_MODEL=gpt-4o-mini
```

### Run

```bash
python app.py
# → http://127.0.0.1:5000
```

### Test

```bash
pip install pytest
pytest
```

## Trade-offs / Known Limitations

- **Serverless + PDF** — `docx2pdf` needs Word; LibreOffice headless needs a large binary not present in most Lambda/Vercel images. On Vercel the app degrades gracefully to DOCX-only. For a production PDF pipeline, the recommended path is a dedicated Gotenberg / LibreOffice-on-Lambda service.
- **No account system yet** — every page load starts fresh except for the localStorage draft (same device, same browser). Multi-device sync would need Supabase/Firebase + auth.
- **Tech & Generic templates** are scaffolded in the registry but fall back to the Finance DOCX until their own `.docx` files are authored.
- **AI features are opt-in** — without an API key, the buttons stay visible but show a friendly "configure `LLM_API_KEY` to enable" tooltip instead of failing silently.
- **Client-side validation only** for now — the backend accepts anything the form sends. Adding a pydantic schema at the `/generate` boundary is the obvious next step.
